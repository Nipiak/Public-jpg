Parcours recommandé

🟢 Semaine 1 — Paliers 1 & 2 (Débutant)

Découverte portail, création utilisateurs, premier enrollment Windows manuel, vérification dsregcmd, groupes dynamiques. Aucun prérequis technique.

🟢 Semaine 2 — Palier 3 (Débutant fin)

Premières politiques de conformité, profils de configuration, déploiement d'apps simples, Update Ring. Commencer à utiliser le portail Intune quotidiennement.

Conditional Access complet : break-glass, MFA, Named Locations, Require Compliant, App Protection Policies BYOD. Section critique pour l'exam.

🔴 Semaine 5 — Paliers 7 & 8 (Expert)

SCEP/Wi-Fi 802.1x, Windows Hello for Business, RBAC+Scope Tags, co-management. Scripts Remediation, Graph API, Win32 avec Dependency.

🔴 Semaine 6 — Palier 9 + Révision (Expert)

Scénarios d'exam complexes intégrant tous les domaines. Simulation d'examen. Révision des pièges classiques. Passage de la certification.

Ex 6
Vérification avec dsregcmd /status
Débutant ⏱ 15 min 🏷 Enrollment
▼
🎯 Objectif : Utiliser dsregcmd /status pour interpréter l'état de jonction et valider l'enrollment Intune depuis la ligne de commande.
⚠ Prérequis : Exercice 5 complété — VM Windows 11 AADJ dans Intune.

Étapes

  1. Sur la VM, ouvrez cmd ou PowerShell (pas besoin d'être admin).
  2. Exécutez : dsregcmd /status
  3. Dans la section Device State, vérifiez :
      • AzureAdJoined : YES ✅
      • DomainJoined : NO (AADJ pur, pas HAADJ)
      • WorkplaceJoined : NO
  4. Dans la section User State, vérifiez :
      • NgcSet : YES (Windows Hello configuré)
      • MdmEnrolled : YES → confirme l'enrollment Intune ✅
  5. Notez le DeviceId — comparez-le avec l'Object ID de l'appareil dans Entra ID.
✅ Résultat attendu : Vous interprétez chaque ligne de dsregcmd /status et pouvez diagnostiquer un problème de jonction à partir de cette sortie seule.
📘 Guide dsregcmd complet 📘 Troubleshoot jonction hybride

A. AzureAdJoined : YES
B. DomainJoined : YES
C. WorkplaceJoined : YES
D. MdmEnrolled : YES

▼
